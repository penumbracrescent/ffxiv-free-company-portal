# Solo Company Workshop planning

Search personal Craft Planner for workshop project names (houses, airships, submarines, etc.). Workshop projects are clearly distinguished from ordinary recipes. Choose project count and included phases in a themed dialog. Combined gathering → crafting stages is the default; choose Phase-by-phase to inspect each phase's checklist or recipe tree.

This is a private browser-saved plan, not a shared FC project. It never submits, reserves, contributes, or creates anything on Workshop & Requests. Its catalog reader uses a read-only transaction and only official `xivapi_company_craft` templates. Standard phase totals are imported directly, not multiplied by their batch count twice. Workshop unlocks are not assumed. Unknown progress results retain standard quantities. Record the actual completed phase result: Excellent removes floor(batchCount/3) batches from the next phase; Outstanding removes floor(2*batchCount/3). This is rounded separately for each project copy and never changes owned/submitted quantities. Missing or inconsistent batch metadata retains standard quantities. Multiple copies share the selected result; create separate projects when their outcomes differ. These results are saved in backups and support undo. The recipe tree numbers every dependency stage, then shows workshop submission phases and a distinct project-output goal. Dashed links show phase order, not extra material demand. Record actual already-submitted quantities separately from already-owned inventory. Exclude phases that are completed or not wanted.

Stock is shared across targets. Phase mode allocates stock once in displayed order and reuses expected earlier batch surplus without adding it to actual inventory. Ownership controls record current inventory; completion checks are reminders, not proof of inventory. Update inventory after consuming it in game. Saved lists, undo/redo, export/restore, vendor/source indicators, crystals, acquisition choices and gear-import handoff continue to apply. Projects retain catalog snapshots so an import refresh cannot silently change a saved list. Edit a project's quantity/phase selection to change its plan.

Timed mining/botany inputs show server-corrected opening/closing countdowns and source coordinates in checklist and tree cards. Active, still-needed materials get a highlighted border. Enable alerts selects the exact game-item/node match and opens the existing alert settings. Existing tracked nodes are retained; permissions are never requested automatically. Site sound works while the planner controller is mounted; background system notifications require explicit permission and the gathering service. These are availability windows, not weather/bait fishing predictions. Stock-covered timed materials cannot start unnecessary alerts. Tree timer controls remain available while exploring or using full screen.

The public release now includes the existing gathering service, same-origin proxy, notification worker, and privacy deletion target for devices. The public service initializes its state directory to UID 1000 (700) then drops to the non-root node user. Keep `data/gathering` private; it contains the push signing key. Backups already include the data directory. Local HTTP supports catalog/site-sound planning; HTTPS (or a browser-supported secure local context) is required for browser push. The service uses an HTTPS-form VAPID subject without changing the configured browser URL. Live installation is not changed by this update.

## Recipe tree refinements

Cards use their natural content height; opening details reflows each column and redraws connections without nested card scrollbars. Hover previews a branch; tapping/clicking its name pins it. Expand/collapse-all controls affect card details only. The checklist/tree choice, zoom and scroll position are remembered per account and saved list in browser storage; view preferences are separate from inventory/undo and backup contents.

Each saved workshop snapshot is compared read-only with the current imported catalog. An older-than-30-days timestamp is a reminder to check, not proof of incorrect data. Updates require a themed preview and explicit Apply, preserve project count/phase choices/progress/submissions/owned inventory, support undo, and refuse to discard submissions on removed materials. Schematic requirements are resolved by exact CompanyCraftSequence → CompanyCraftDraft game IDs through server-side cached XIVAPI requests. Unknown or unavailable data is labeled unverified. One-time schematic costs remain separate from project materials. FC access/unlock status is never inferred; the user's optional confirmation is local only.

## Research sources

- [Teamcraft item lists](https://wiki.ffxivteamcraft.com/base-features/items-lists): consolidated inputs, workshop support, saved lists and inventory-aware planning.
- [Workshop phase feature request](https://github.com/ffxiv-teamcraft/ffxiv-teamcraft/issues/2269): users struggle to follow large multi-phase workshop lists. This informed the optional phase layout, project quantities and explicit turn-in batches.
- [Consumed-material indicator complaint](https://github.com/ffxiv-teamcraft/ffxiv-teamcraft/issues/1721): availability indicators can become misleading when materials have already been consumed. Submitted amounts are separate from stock, with no duplicate credit across phases.
- [Crafting as a Service](https://ffxivcrafting.com/) and [Garland Tools](https://garlandtools.org/db/): simple search, consolidated materials and approachable source information. Keep the combined view simple and phase complexity optional.
- [User feedback comparing planners](https://www.reddit.com/r/ffxiv/comments/npjl1k) and [recipe-tree appreciation](https://www.reddit.com/r/ffxiv/comments/rqtagc): convenience and understandable solo lists matter as much as feature count. Existing source badges, tree/checklist toggle, inline owned quantities and shared alert settings are reused.

User feedback is qualitative, not a benchmark or a source of recipe quantities. All actual workshop quantities come from the imported game catalog. No game automation or inventory scraping is used.
